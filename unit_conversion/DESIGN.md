## 1. 개요

### 1.1 목적
기존 SI·야드파운드·척관법에 존재하지 않는 신규 단위계 **메르헨 단위계(Märchen Unit System)** 를 정의하고,
**기존 단위로 표현된 값을 메르헨 단위로 변환**하는 웹 페이지를 제작한다.

### 1.2 범위
- 지원 차원(dimension): **길이 / 넓이 / 부피 / 무게** 4종
- 입력은 그 차원의 **모든 단위**(메르헨 포함), 출력은 단위계가 정하는 한 단위 (§3.5)
- 단일 페이지 웹 애플리케이션 (정적 호스팅 가능, 서버 불필요)
- 오프라인 동작, 외부 의존성 없음

### 1.3 범위 밖 (v1 제외)
- **도형 도우미** (한 변 `a` mt → 넓이 `a²` dt, 부피 `a³` dtt) — 필요 시 v2에서 구현
- 온도·시간·속도 등 기타 차원
- 사용자 정의 단위 추가 UI (데이터 파일 수정으로만 확장)
- 계정 / 서버 / DB

## 2. 메르헨 단위계 정의

### 2.1 기본 단위

| 기호 | 읽는 법 | 차원 | 정의 |
|---|---|---|---|
| `mt` | 메따 | 길이 | **1 mt = 14 cm** (기본 정의) |
| `dt` | 듀따 | 넓이 | **1 dt = 1 mt² = 196 cm²** |
| `dtt` | 뜌따따 | 부피 | **1 dtt = 1 mt³ = 2744 cm³ = 2.744 L** |
| `tht` | 댕따 | 무게 | **1 tht = 5 kg** (기본 정의) |

각 차원마다 메르헨 단위는 **정확히 하나씩**이다. 따라서 차원을 고르면 출력 단위가 자동으로 결정된다.

### 2.2 단위계 구조
`mt`와 `tht`가 **독립 기본 단위**이고, `dt`·`dtt`는 `mt`에서 파생된 **유도 단위**다.

```
mt (길이, 14 cm)
 ├─ 제곱   → dt  (넓이, 196 cm²)
 └─ 세제곱 → dtt (부피, 2.744 L)

tht (무게, 5 kg)   ← 독립
```

### 2.3 표기 규칙
- 기호는 **항상 소문자**로 표기한다: `mt`, `dt`, `dtt`, `tht`.
- 대문자(`MT`, `Dt`)나 혼용 표기는 사용하지 않으며, 코드·UI·문서 전부 소문자로 통일한다.
- 소스 코드의 단위 `id` 역시 소문자 문자열을 그대로 쓴다.
- 값과 기호 사이는 한 칸 띄운다: `3 mt` (O), `3mt` (X).
- 읽는 법은 UI 안내 패널에 한글로 병기한다 (메따 / 듀따 / 뜌따따 / 댕따).

### 2.4 `dtt` 값 확정
원 명세에는 `1 dtt = 2.74 L`로 기재되어 있었으나, 정의식 `1 dtt = 1 mt³`를 전개하면
`14³ = 2744 cm³ = 2.744 L`이다. **정확한 수치인 2.744 L을 채택한다.**

```js
export const MT_IN_CM = 14;
export const DTT_IN_L = MT_IN_CM ** 3 / 1000;  // 2.744 — 정의식에서 유도
```

상수를 직접 쓰지 않고 `MT_IN_CM`에서 유도하도록 작성해, `mt` 정의가 바뀌어도
`dt`·`dtt`가 자동으로 따라오게 한다. 이 일관성은 테스트 T-15, T-16으로 고정한다.

## 3. 변환 규격

### 3.1 변환 모델
모든 변환은 **차원별 기준 단위(base unit)를 경유하는 2단계 변환**으로 처리한다.
단위 간 N×N 변환표를 만들지 않고, 각 기존 단위가 "기준 단위 대비 배율(factor)" 하나만 갖는다.

```
입력값(기존 단위) ──× factor(기존)──▶ 기준 단위 값 ──÷ factor(목표)──▶ 출력값(목표 단위)

value_base    = value_in   × factor(fromUnit)
value_out    = value_base ÷ factor(target)
```

### 3.2 차원별 기준 단위와 출력 단위

| 차원 | 기준 단위 | 출력(메르헨) 단위 | 출력 단위 factor |
|---|---|---|---|
| 길이 | `cm` | `mt` | 14 |
| 넓이 | `cm²` | `dt` | 196 |
| 부피 | `L` | `dtt` | 2.744 |
| 무게 | `kg` | `tht` | 5 |

기준 단위는 명세의 정의가 기술된 단위를 그대로 채택해, 정의값이 코드에 오차 없이 들어가도록 했다.

### 3.4 차원 간 변환 금지
`mt`(길이) · `dt`(넓이) · `dtt`(부피)는 **서로 변환할 수 없다**.
`dt = mt²`는 단위의 *정의 관계*이지 값의 변환 관계가 아니다 (3 mt는 3 dt가 아니다).
UI에서 차원이 다른 단위는 선택 목록에 노출되지 않으므로 원천 차단된다.
길이값으로부터 넓이·부피를 얻는 계산(도형 도우미)은 아직 없다.

### 3.5 결과 단위계 선택 (v2.0)

결과를 어느 단위계로 낼지 고를 수 있다. **기본값은 메르헨 단위계**다.

| 차원 | 메르헨 | 야드파운드 |
|---|---|---|
| 길이 | `mt` 메따 | `ft` 피트 |
| 넓이 | `dt` 듀따 | `ac` 에이커 |
| 부피 | `dtt` 뜌따따 | `gal` 갤런(미) |
| 무게 | `tht` 댕따 | `lb` 파운드 |

**야드파운드 단위는 배율을 새로 적지 않는다.** `ft`·`ac`·`galUS`·`lb`는 이미 §3.3의
입력 단위 목록에 배율과 함께 들어 있으므로, 차원 정의에서는 그 단위를 **id로 가리키기만** 한다.

```js
imperial: 'ft',   // sources에 이미 있는 단위를 가리킨다
```

같은 배율이 두 곳에 생기면 한쪽만 고쳐 어긋날 수 있다. 테스트 T-42가
"야드파운드 목표 단위가 `sources`의 그 단위와 **같은 객체**인지"를 확인해 이 규칙을 고정한다.

전환하면 결과·변환식·한눈에 보기·차원 탭 아래 기호가 모두 따라 바뀐다.
다만 **단위 안내 패널은 고정**이다 — 이 앱의 주제인 메르헨 단위계 설명이기 때문이다.

### 3.6 "다른 단위로 본다면" 표 (v2.6)

결과 패널이 한 단위만 보여주는 것과 달리, 이 표는 **입력 수량을 그 차원의 모든 단위로**
환산해 늘어놓는다. `1 cm`를 넣으면 `10 mm` · `0.01 m` · `0.39 in` · `0.07 mt` 식이다.

- 목록은 `dim.allUnits` = **메르헨 단위 + 입력 단위 전체**다. 메르헨 단위를 맨 앞에 두어
  이 앱의 주인공이 먼저 눈에 들어오게 한다.
- 기준 단위를 한 번만 구하고 단위마다 나누기만 한다 (`toAllUnits`).
- 제목이 곧 설명이다: `1 cm를 다른 단위로 본다면`. 입력이 비었거나 잘못됐을 때만
  중립 제목으로 돌아가고 안내 문구가 뜬다.
- 행을 누르면 그 단위가 입력 단위가 된다. **메르헨 행도 마찬가지다** — v2.7부터
  메르헨 단위를 입력으로 고를 수 있어, 예전의 `is-static` 제약은 사라졌다.

### 6.1 기술 스택
- **HTML5 + CSS3 + Vanilla JavaScript (ES2020)**
- 빌드 도구·프레임워크 없음 — 파일을 열면 바로 동작

선정 이유: 계산 로직이 순수 함수 몇 개로 끝나는 규모라 프레임워크 도입 비용이 이득을 넘는다.
정적 호스팅(GitHub Pages 등) 또는 로컬 파일로 그대로 배포할 수 있다.

**실행 방식 (v1.3 확정)**
이 페이지는 완전한 정적 페이지이므로 **웹 서버를 띄우지 않는다.**
`index.html`을 파일 탐색기에서 더블클릭하거나 브라우저로 여는 것이 표준 실행 방법이며,
데모·검증도 같은 방식으로 한다.

**스크립트 로딩 방식 (v1.2 조정)**
`<script type="module">`은 `file://` 프로토콜에서 CORS 정책에 막혀 로드되지 않는다.
위 실행 요건을 지키기 위해 **클래식 스크립트 + 전역 네임스페이스**로 구현한다.

```html
<script src="js/i18n.js"></script>     <!-- MU.i18n    -->
<script src="js/units.js"></script>    <!-- MU.units   -->
<script src="js/convert.js"></script>  <!-- MU.convert -->
<script src="js/format.js"></script>   <!-- MU.format  -->
<script src="js/storage.js"></script>  <!-- MU.storage -->
<script src="js/ui.js"></script>       <!-- 진입점     -->
```

각 파일은 IIFE로 감싸 `window.MU` 아래 네임스페이스 하나씩만 노출한다.
파일 분리와 단방향 의존 관계(§6.2)는 그대로 유지되며, 향후 번들러를 도입하면
IIFE 껍데기만 `export`로 바꾸면 된다.

### 6.4 언어 (v2.3 · v2.5)

화면 문구는 `js/i18n.js` 한 곳에 ko·en 표로 모은다. 기본은 **한국어**이고, 헤더 오른쪽 위
토글로 바꾸며 선택은 localStorage에 남는다.

단위·차원·단위계처럼 **데이터에 딸린 이름은 units.js가 `{ko, en}`으로 갖고** `i18n.pick()`이 고른다.
문구 표에 따로 두면 단위 목록과 번역 표가 따로 놀 수 있기 때문이다.

`pick()`은 **문자열을 그대로 통과시킨다.** `mm`·`kg`처럼 어느 언어에서나 같은 값을
두 번 적지 않기 위해서다. 그래서 `symbol`은 보통 문자열 하나이고, 라틴 표기가 따로 필요한
척관법 기호 7종(尺·평·되·말·컵·근·관)만 `{ko, en}`이다 — 이게 없으면 영문 화면의 변환식이
`1,234 근 = …`처럼 영어 사용자가 읽지도 타이핑하지도 못하는 모양이 된다 (T-50).

`format.parseInput()`은 오류 **문구 대신 코드**(`errNegative` 등)를 돌려준다.
화면 언어가 둘인 이상 계산 모듈이 UI 문구를 들고 있으면 안 된다 — 번역은 UI가 맡는다.

정적 HTML 문구는 `data-i18n`(본문) · `data-i18n-html`(태그 포함) · `data-i18n-aria` ·
`data-i18n-title` · `data-i18n-placeholder` 속성으로 표시하고 `applyStaticText()`가 한 번에 채운다.
전환하면 `<html lang>`과 `<title>`도 함께 바뀐다.

워드마크 부제는 **일부러 반대 언어**로 단다. 이런 문구에는 `data-i18n-lang`으로 개별 `lang`을
붙여야 한다 — 없으면 스크린 리더가 페이지 언어로 발음하려 들어 알아들을 수 없는 소리를 낸다 (T-53).

두 언어의 문구 키가 어긋나면 그 자리가 조용히 비므로, 테스트 T-45·T-46이
**키 일치와 데이터 이름의 ko·en 채움**을 확인한다.

## 7. 데이터 모델

### 7.1 스키마 (`js/units.js`)

```js
/**
 * @typedef {Object} Unit
 * @property {string} id      고유 키 — 소문자 (예: 'cm', 'mt')
 * @property {string} name    표시명 (예: '센티미터')
 * @property {string} symbol  기호 (예: 'cm')
 * @property {number} factor  기준 단위 환산 배율
 */

/**
 * @typedef {Object} MarchenUnit
 * @property {string} id       'mt' | 'dt' | 'dtt' | 'tht'
 * @property {string} reading  읽는 법 (예: '메따')
 * @property {number} factor   기준 단위 환산 배율
 * @property {string} note     정의 문구 (예: '1 mt = 14 cm')
 */

/**
 * @typedef {Object} Dimension
 * @property {string}       id       'length' | 'area' | 'volume' | 'mass'
 * @property {string}       label    '길이' | '넓이' | '부피' | '무게'
 * @property {MarchenUnit}  target   해당 차원의 출력 단위 (1개 고정)
 * @property {string}       defaultFrom 기본 선택 입력 단위 id
 * @property {Unit[]}       sources  입력 가능한 기존 단위 목록
 */
```

`Dimension.target`이 한 개로 고정된다는 점이 v1 설계의 핵심이다.
출력 단위 선택 UI가 필요 없고, 변환 함수 시그니처도 단순해진다.

### 7.2 데이터 예시

```js
export const MT_IN_CM  = 14;
export const DT_IN_CM2 = MT_IN_CM ** 2;        // 196
export const DTT_IN_L  = MT_IN_CM ** 3 / 1000; // 2.744
export const THT_IN_KG = 5;   // 내부 상수 — 외부로 내보내지 않는다

export const DIMENSIONS = [
  {
    id: 'length', label: '길이', defaultFrom: 'm',   // 기본: 미터 → 메따
    target: { id:'mt', reading:'메따', factor: MT_IN_CM, note:'1 mt = 14 cm' },
    sources: [
      { id:'mm', name:'밀리미터', symbol:'mm', factor: 0.1 },
      { id:'cm', name:'센티미터', symbol:'cm', factor: 1 },
      { id:'m',  name:'미터',    symbol:'m',  factor: 100 },
      // ...
    ]
  },
  {
    id: 'volume', label: '부피', defaultFrom: 'L',
    target: { id:'dtt', reading:'뜌따따', factor: DTT_IN_L, note:'1 dtt = 1 mt³ = 2.744 L' },
    sources: [ /* ... */ ]
  },
  // area / mass ...
];
```

로딩 시점에 각 unit에 소속 `dimension` id를 주입하고 `Object.freeze`로 동결한다.

## 8. 변환 엔진

### 8.1 핵심 API (`js/convert.js`)

```js
/** 기존 단위 값 → 기준 단위 값 (변환 1단계). 모듈 내부 전용 — 내보내지 않는다 */
function toBase(value, unit) { return value * unit.factor; }

/**
 * 기존 단위 → 해당 차원의 메르헨 단위로 변환
 * @param {number} value
 * @param {Unit} fromUnit      입력 단위 (기존 단위)
 * @param {Dimension} dimension
 * @returns {number} 메르헨 단위 값
 * @throws {DimensionMismatchError} fromUnit이 해당 차원 소속이 아닐 때
 */
export function toMarchen(value, fromUnit, dimension) {
  if (fromUnit.dimension !== dimension.id) throw new DimensionMismatchError();
  return toBase(value, fromUnit) / dimension.target.factor;
}

/** 입력 수량을 차원 안의 모든 단위로 환산한다 (F-05) */
export function toAllUnits(value, fromUnit, dimension) {
  if (fromUnit.dimension !== dimension.id) throw new DimensionMismatchError();
  const base = toBase(value, fromUnit);          // 기준 단위는 한 번만 구한다
  return dimension.allUnits.map(u => ({ unit: u, value: base / u.factor }));
}
```

### 8.2 정밀도 정책
- 내부 계산은 항상 `number`(double) 원시값으로 유지하고, **표시 단계에서만 반올림**한다.
- 기준 단위와 출력 단위가 일치하는 조합은 존재하지 않으므로 항등 예외 처리는 불필요하다.
- 포맷된 문자열 결과를 다시 계산 입력으로 재사용하지 않는다 (오차 누적 방지).
- `dt`·`dtt` factor는 리터럴이 아니라 `MT_IN_CM`에서 유도해 정의 일관성을 유지한다 (§2.4).

### 8.3 입력 파싱 규칙

| 입력 | 처리 |
|---|---|
| `` (빈 문자열) | 결과 영역 비움, 오류 아님 |
| `1,234.5` | 천 단위 쉼표 제거 후 파싱 |
| `,` · `,,,` | `유효한 숫자를 입력하세요` — **빈칸 판정을 쉼표 제거보다 먼저** 해서 '빈 입력'으로 둔갑하지 않게 한다 |
| `1e3`, `1.2E-4` | 지수 표기 허용 |
| `-5` | **거부** — `음수는 입력할 수 없습니다` 오류 메시지, 결과 비움 |
| `abc`, `1.2.3` | `유효한 숫자를 입력하세요` 오류 메시지 |
| `Infinity`, 오버플로 | `표현할 수 없는 값입니다` 오류 메시지 |

음수는 길이·넓이·부피·무게 어느 차원에서도 물리적 의미가 없으므로 계산 자체를 수행하지 않는다.

### 8.4 출력 포맷 규칙 (`js/format.js`)

표기 기준은 **소수점 자리수(decimals)** 이며 기본값은 **2자리**다.

```
|v| = 0                     → "0"
|v| ≥ 1e12                  → 지수 표기
|v| < 0.5 × 10^(-d)         → 지수 표기   ← d자리로 반올림하면 0이 되는 값
그 외                        → 소수점 최대 d자리 · 3자리 쉼표 · 끝자리 0 제거
```

세 번째 규칙이 핵심이다. `1 mg = 0.0000002 tht`를 2자리로 자르면 `0.00`이 되어
**값이 있는데 없는 것처럼 보인다.** 이런 값은 뭉개지 않고 `2e-7`로 표기한다.

끝자리 0은 제거한다 — `10.00`이 아니라 `10`으로 표시한다 ("2자리**까지만**").

기본값(소수점 2자리) 표기 예:

| 입력 | 출력 |
|---|---|
| 1 m | `7.14 mt` |
| 1.4 m | `10 mt` |
| 1 km | `7,142.86 mt` |
| 1 cm | `0.07 mt` |
| 1 kg | `0.2 tht` |
| 1 mg | `2e-7 tht` |

**변환식(§9.1)의 좌변은 반올림하지 않는다.** 사용자가 친 원문을 그대로 되비춘다.
`2.744 L`을 입력했는데 좌변이 `2.74 L`로 보이면 입력을 왜곡하기 때문이다.

```
└──────────────────────────────────────────────────────┘
```

- 입력 카드와 결과 카드를 **세로 2단**으로 쌓고, 사이에 ▼ 화살표를 배치

### 9.4 시각 규칙
- 결과(메르헨 값)는 화면에서 가장 큰 타이포로 배치하고, 아래에 읽는 법(메따)을 병기한다.
- 메르헨 단위 기호는 강조색으로 표시해 기존 단위와 시각적으로 구분한다.

정의되어 있어, 진홍을 바탕으로 금색을 강조색으로 쓰는 위계를 그대로 따랐다.

#### 타이포그래피

| 용도 | 스택 | 비고 |
|---|---|---|
| 표제 (`--serif`) | Georgia → Times New Roman → Noto Serif KR → Batang | 원본의 Clarendon 슬랩세리프를 대신하는 시스템 세리프 |
| 숫자 (`--serif-num`) | Times New Roman → Times → Noto Serif KR | **별도 스택인 이유는 아래 참고** |
| 본문 (`--sans`) | Pretendard → Apple SD Gothic Neo → Malgun Gothic | 원본도 본문은 산세리프(Noto Sans KR) |
| 기호 (`--mono`) | SFMono → Consolas | `mt` `dt` `dtt` `tht` 표기 전용 |

> **숫자 스택을 나눈 이유**: Georgia의 기본 숫자는 올드스타일 figure라 `7`과 `4`의
> 높이가 제각각이라 변환 결과를 읽기 나쁘다. 변환기의 본분은 숫자 가독성이므로
> 숫자가 들어가는 요소(결과 · 변환식 · 입력창 · 환산표)만 라이닝 숫자를 쓰는
> Times 계열로 분리하고 `font-variant-numeric: lining-nums tabular-nums`를 건다.
> 웹폰트는 쓰지 않는다 — `file://` 오프라인 실행이 전제라 네트워크에 의존할 수 없다.

#### 구성 요소

| 요소 | 처리 |
|---|---|
| 문장 배너 | 진홍 바탕 + 위아래 4px 금색 테두리 + 안쪽 1px 금색 이중선 |
| 왕관 문장 | 인라인 SVG (왕관 + 보석 3). 원본 문장의 복제가 아닌 일반 문양 |
| 구분선 | 양옆으로 금색 선이 뻗고 가운데 `✦` |
| 차원 탭 | 진홍 리본 위의 탭. 활성 탭은 금색 바탕 + 진홍 글자 |
| 결과 패널 | 진홍 바탕에 금색 숫자 — 화면의 옥좌. 안쪽에 금색 테두리 한 겹 |
| 소수점 선택 | 결과 패널 머리줄 오른쪽. 진홍 위에 올라가므로 복사 버튼과 같은 금색 외곽선 차림새 |
| 섹션 제목 | 세리프 제목 + 오른쪽으로 뻗는 금색 선 |
| 패널 | 위쪽에 3px 진홍 띠 (원본의 붉은 배너 구분자에서 따옴) |

#### 단일 테마 (v1.5 확정)

**다크 모드를 두지 않는다.** 진홍·금색·양피지 조합 하나로 고정한다.

- `prefers-color-scheme` 분기와 다크용 토큰 재정의를 전부 걷어냈다.
- 대신 `:root`에 **`color-scheme: light`** 를 선언한다.
  이게 없으면 OS가 다크 모드일 때 `select` 드롭다운·스크롤바 같은
  브라우저 기본 UI만 제멋대로 어두워져 양피지 지면과 따로 논다.
- 강조 글자색은 진홍(`--red`) 하나로 되돌렸다. 테마별로 색을 뒤집던
  `--accent-text` 토큰은 존재 이유가 사라져 제거했다.

### 9.6 프로토타입 디자인 보관

첫 프로토타입 디자인(연보라 계열, 시스템 산세리프)은 `prototype/`에 **자기 완결형 사본**으로
보관한다. `css`와 `js` 사본을 자체적으로 갖고 있어 상위 폴더 변경에 영향받지 않으며,
`prototype/index.html`을 더블클릭하면 그대로 실행된다.

기능 수정은 언제나 상위 폴더에서 하고, `prototype/`은 건드리지 않는다.
바꿔 말해 상위 폴더의 기능 변경은 보관본에 반영되지 않는다 — 의도된 동결이다.

- **굿즈(마플샵)**: 마플샵은 워드마크만 쓰고 압축할 심볼이 없어, 굿즈를 뜻하는 쇼핑백으로 대신했다.
- **네이버 카페**: 카페 앱 아이콘을 확인할 수 없어 상위 브랜드인 네이버의 N 마크를 썼다.
  커피잔은 카페가 커뮤니티라는 성격을 오해하게 만들어 쓰지 않았다.
- **제국 홈페이지**: 페이지 머리의 왕관 문장(§9.5)을 그대로 재사용한다. 같은 마크를 두 번 그리지 않는다.

색은 **브랜드 색 대신 제국 색**(진홍 아이콘 · 금색 테두리)을 쓴다. 유튜브 빨강과
치지직 형광 초록을 그대로 쓰면 양피지 지면과 따로 논다. 호버 시 진홍으로 채워진다.

외부로 나가는 링크이므로 `target="_blank"`에 `rel="noopener noreferrer"`를 함께 건다.
아이콘만 있는 버튼이라 접근성 이름은 `aria-label`로 주고, 장식인 `<svg>`는 `aria-hidden`으로 가린다.
