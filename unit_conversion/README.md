# 메르헨 단위계 변환기

SI · 야드파운드 · 척관법 · 메르헨 단위로 표현된 값을 **메르헨 단위계** 또는 **야드파운드**로
변환하는 웹 페이지입니다.

| 기호 | 읽는 법 | 차원 | 정의 |
|---|---|---|---|
| `mt` | 메따 | 길이 | 1 mt = 14 cm |
| `dt` | 듀따 | 넓이 | 1 dt = 1 mt² = 196 cm² |
| `dtt` | 뜌따따 | 부피 | 1 dtt = 1 mt³ = 2.744 L |
| `tht` | 댕따 | 무게 | 1 tht = 5 kg |

입력은 그 차원의 **모든 단위**(메르헨 단위 포함)에서 고를 수 있고, 출력은 고른 단위계의
단위 하나로 냅니다. 도형 변환은 아직 없습니다.

## 실행

**`index.html`을 더블클릭**하면 됩니다. 웹 서버도, 빌드 과정도 필요 없습니다.

```bash
start index.html
```

받지 않고 바로 보려면 → **https://swi0110.github.io/this1_project/unit_conversion/**

GitHub Pages가 `master`를 서빙하므로, 작업 브랜치의 변경은 머지한 뒤에 반영됩니다.

## 화면

- **언어** — 배너 오른쪽 위 `KO` / `EN`. 기본은 한국어이며 선택은 저장됩니다.
- **차원** — 길이 / 넓이 / 부피 / 무게 탭. 탭 아래 기호가 그 차원의 출력 단위입니다.
- **입력 단위** — 그 차원의 모든 단위에서 고릅니다. 메르헨 단위(`mt` 등)도 입력할 수 있어
  `3 mt`를 넣고 야드파운드로 바꾸면 `1.38 ft`가 나옵니다.
- **다른 단위로 본다면** — 입력 수량을 그 차원의 모든 단위로 환산해 보여줍니다.
  메르헨 단위가 맨 위에 오고, 행을 누르면 그 단위가 입력 단위가 됩니다.
- **결과 단위계** — 결과 카드 아래 `메르헨 단위계` / `야드파운드`. 기본은 메르헨입니다.
  야드파운드는 길이 `ft` · 넓이 `ac` · 부피 `gal` · 무게 `lb`로 냅니다.
- **소수점** — 결과 카드 머리줄에서 2 / 4 / 6 / 8자리. 기본은 2자리입니다.

기본 화면은 **미터(m) → 메따(mt)**, 소수점 2자리입니다.

## 디자인

정규 버전은 [The Holy Maerchen Empire](https://www.theholymaerchenempire.com/)의
제국 문장 스타일을 참고했습니다 — 진홍(`#c2292f`) 바탕에 금색(`#ffc786`) 세리프,
금색 헤어라인, 왕관 문양. **단일 테마이며 다크 모드는 두지 않습니다** — OS가 다크 모드여도
라이트 테마 그대로 표시됩니다.

첫 프로토타입 디자인은 [prototype/](prototype/)에 자기 완결형 사본으로 보관되어 있습니다.
`prototype/index.html`을 더블클릭하면 그대로 실행됩니다. **기능 수정은 상위 폴더에서만 하고
보관본은 건드리지 않습니다** — 의도된 동결이라 상위 폴더의 변경은 반영되지 않습니다.

## 입력 단위 추가하기

`js/units.js`의 해당 차원 `sources` 배열에 객체 하나만 넣으면 드롭다운과 환산표에
자동 반영됩니다. 다른 파일은 수정할 필요가 없습니다.

```js
{ id: 'chi', symbol: 'chi', factor: 3.0303, name: { ko: '치', en: 'Chi' } }
```

- **`name`은 반드시 `{ko, en}`** 입니다. 문자열 하나만 적으면 두 언어에 같은 문구가 나와
  번역이 빠진 줄 모르고 지나갑니다.
- **`symbol`은 보통 문자열 하나**면 됩니다 (`mm`, `kg`처럼 어느 언어에서나 같으므로).
  한글·한자 기호라 라틴 표기가 따로 필요할 때만 `{ko: '근', en: 'geun'}`처럼 적습니다.
  이게 없으면 영문 화면의 변환식이 `1,234 근 = …`처럼 영어 사용자가 읽지도
  타이핑하지도 못하는 모양이 됩니다.
- `factor`는 그 차원의 **기준 단위** 기준 배율입니다 (길이 `cm`, 넓이 `cm²`, 부피 `L`, 무게 `kg`).

## 화면 문구 고치기

`js/i18n.js`의 `STRINGS.ko` / `STRINGS.en`에서 고칩니다. **두 언어의 키가 어긋나면
전환했을 때 그 자리가 조용히 비므로**, 키는 반드시 양쪽에 같이 넣습니다.

정적 HTML 문구는 `data-i18n` 계열 속성으로 표시하면 `applyStaticText()`가 채웁니다.

| 속성 | 채우는 곳 |
|---|---|
| `data-i18n` | 본문 텍스트 |
| `data-i18n-html` | 태그가 섞인 본문 |
| `data-i18n-aria` | `aria-label` |
| `data-i18n-title` | `title` |
| `data-i18n-placeholder` | `placeholder` |
| `data-i18n-lang` | `lang` — 페이지 언어와 다른 언어로 적힌 문구에만 |

## 설계 참고

- **이 저장소에는 자동 테스트가 없습니다.** 아래 규칙과 위의 단위·문구 추가 규칙은
  직접 지켜야 합니다.
- `dt`·`dtt`의 배율은 리터럴이 아니라 `MT_IN_CM`에서 유도합니다. `mt` 정의가 바뀌면
  유도 단위가 자동으로 따라옵니다.
- 야드파운드 출력 단위는 배율을 새로 적지 않고 `sources`에 이미 있는 단위를 id로
  가리킵니다. 배율이 두 벌이 되면 한쪽만 고쳐 어긋나기 때문입니다.
- 길이 · 넓이 · 부피는 **서로 변환되지 않습니다**. `1 dt = 1 mt²`는 단위의 정의 관계이지
  값의 변환 관계가 아닙니다 (3 mt는 3 dt가 아닙니다).
- 음수 입력은 받지 않습니다. 쉼표만 친 입력도 '빈 입력'이 아니라 오류로 안내합니다.
- 소수점 2자리로 반올림하면 0이 되는 작은 값(`1 mg = 0.0000002 tht`)은 `0.00`으로 뭉개지 않고
  `2e-7`처럼 지수 표기로 보여줍니다. 값이 있는데 없는 것처럼 보이는 것을 막기 위해서입니다.
- `format.parseInput()`은 오류 **문구가 아니라 코드**(`errNegative` 등)를 돌려줍니다.
  화면 언어가 둘이라 번역은 UI가 맡습니다.
- `<script type="module">`은 `file://`에서 CORS에 막히므로, 클래식 스크립트 +
  `window.MU` 네임스페이스로 구현했습니다. 파일 분리와 단방향 의존 구조는 그대로입니다.
